# Checks on stories and components

Candidate automatic checks on the stories and components of `libs/ui/core` (`@numen/ui`) and `libs/ui/shell` (`@numen/shell`). Each row says what the check forbids, how it is decided by structure, whether it exists in the repository now, how many violations `main` has, and a recommendation. A check decides by structure (`AGENTS.md` section 15, rule 10): an off-the-shelf tool with configuration where one exists, otherwise a syntax tree, the import graph or type information; it never matches a regular expression over source text. The registered verifiers are printed by `node tools/lint-layers/check.mjs --list`.

The counts were taken by reading the code and with read-only scripts over `libs/ui/*/src` at the commit this file was written at (29 story files with 265 stories, 51 `.vue` files, 25 in core and 26 in shell). Nothing was run that needs a browser, so the counts of axe violations and of the plugin rules that are not installed are unknown and said so.

## Reading the table

- Cheap means a configuration of an installed tool or one verifier in `tools/lint-layers` over an AST or the import graph, with a violation fixture in `tools/lint-layers/checks.test.mjs`. Needs design means the rule depends on a decision the owner has not made, or on a dependency the owner approves.
- A check that fails on `main` today is fixed in the code, not by a list of exceptions (`AGENTS.md` section 15, rule 11). The two checks with violations that are rewrites (style text, lengths) are therefore built together with the change that removes the findings.
- `reach: false` and `reach: { keeps }` in the keyboard walk are per-story opt-outs. They are an exclusion by name in `parameters`; a stricter walk would derive the case from structure (a component that keeps Tab is a modal or a text field) and drop the parameter.

## Recommendation

Build, in this order:

- The import block applied to stories and fixtures (configuration only, zero findings).
- Every public component has a story, and every emitting component has a story with a `play` function (one verifier, two findings: `DragPreview`, `Prose`).
- The typed style-text rule, together with the deletion of the contrast, sizing and window-size stories and the style reads in the other stories.
- The cheap token parts (`dark:`, palette and arbitrary classes, font and duration literals), which keep at zero what is zero now.
- `eslint-plugin-storybook` recommended rules without `csf-component`.

Decide with the owner before building:

- `@storybook/addon-a11y` and its `color-contrast` rule, and the dependency on `eslint-plugin-vuejs-accessibility`: a dependency is the owner's decision, and the violation counts are measured on mridanga after installing.
- Whether component-local lengths are tokens.
