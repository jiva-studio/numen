# Checks on stories and components

Candidate automatic checks on the stories and components of `libs/ui/components` (`@numen/ui`) and `libs/ui/workbench` (`@numen/workbench`). Each row says what the check forbids, how it is decided by structure, whether it exists in the repository now, how many violations `main` has, and a recommendation. A check decides by structure (`AGENTS.md` section 15, rule 10): an off-the-shelf tool with configuration where one exists, otherwise a syntax tree, the import graph or type information; it never matches a regular expression over source text. The registered verifiers are printed by `make checks --list`.

The counts were taken by reading the code and with read-only scripts over `libs/ui/*/src` at the commit this file was written at (29 story files with 265 stories, 51 `.vue` files, 25 in components and 26 in workbench). Nothing was run that needs a browser, so the counts of the plugin rules that are not installed are unknown and said so. The rows are candidates; the owner has decided which are built (see "Recommendation").

## Reading the table

- Cheap means a configuration of an installed tool or one check in `tools/checks` over an AST or the import graph, with a planted-violation test beside it. Needs design means the rule depends on a decision the owner has not made, or on a dependency the owner approves.
- A check that fails on `main` today is fixed in the code, not by a list of exceptions (`AGENTS.md` section 15, rule 11). The two checks with violations that are rewrites (style text, lengths) are therefore built together with the change that removes the findings.

## Recommendation

Decided: no `@storybook/addon-a11y` (axe), no `eslint-plugin-vuejs-accessibility`, and no contrast, sizing or window-size stories. A `rem` or `em` literal may stand on a property; no `px` for a size except a 1px hairline border; a custom property outside the token files holds a length only when a token file declares it. The stylelint rule `numen/no-bare-length` checks lengths.

The three checks that are built, by Package F25, once the components and stories they refuse are fixed:

- Every public component has a story.
- Every emitting component has a story with a `play` function (the first two rows are one verifier; today's findings are `DragPreview` and `Prose`).
- `eslint-plugin-storybook` with its recommended rules and `csf-component` off.

The typed style-text rule is built (`numen/no-style-declaration-read`). The other rows of the table stay candidates until the owner picks one: the cheap token parts (`dark:`, palette and arbitrary classes, font and duration literals), the role-and-name query rule and the story doc comment.
