Type. There is nothing to press.

A note is saved to its file automatically: about a second after you stop typing, and in any case within
five seconds of the first change you made. <kbd>Ctrl</kbd>/<kbd>⌘</kbd> <kbd>S</kbd> writes the unsaved
changes at that moment, for the times you want to be sure. Closing a tab or quitting the window
writes the unsaved changes and waits for them.

Everything you write is found by name and by word as soon as it is saved. Search
[by meaning](/search/) is updated a few seconds after you stop typing.

## What you see as you write

The note is markdown, and it is shown formatted: a heading is a heading, a link is a
link, a list is a list. The markdown marks appear on the line the caret is on, so you can edit
them, and they are hidden again when you move away.

## Linking as you type

Typing `[[` opens an autocomplete list of existing notes in the vault.

- Filter note titles and paths as you type.
- <kbd>↑</kbd> and <kbd>↓</kbd> navigate choices; <kbd>Enter</kbd> or <kbd>Tab</kbd> inserts the
  link.
- Selecting a title that does not yet exist creates a new note in the vault and inserts `[[New Note]]` without losing your place.

## What names a note

Two things: a `title:` in the frontmatter if the note has one, and otherwise the filename.

**A heading in the document does not define a note title.** Writing `# Something` at the top of a note does not
rename it, and neither does changing one. What you type in the body is the body.

## Making one

**Create note** in the commands asks for a title, and the file is named after it. Characters a
filename cannot hold — `/ \ : * ? " < > |` and a few more — become `-`, and a very long title is
shortened to fit.

If the title is unchanged by that, the filename is the title and nothing is written inside the
note. Otherwise the frontmatter contains your exact title under `title:`, so the name
you meant is kept intact.

Two notes may share a name. numen tells you when this happens and saves both.

## Renaming

**Rename note** changes whichever of the two gives the note its name: the `title:` key if it has one,
and otherwise the filename.

**The title and the filename are kept as one name.** Change the title and the file moves to
match; rename the file — in the [files tab](/files/) or in your own file manager —
and the new name is written into the note. A note that only has a filename is unaffected: there
is nothing inside it to update.

If you would rather they were two separate things, **Sync title and filename** in the commands
turns it off and on again, and saves the choice. It is
`app.naming.syncTitleAndFilename` in [the settings](/settings/) if you would rather edit the
file. Off, a new title stays inside the note and a renamed file stays renamed.

The `title:` key is added only where a filename cannot hold the whole title, so a vault whose
filenames match its titles has no `title:` keys.

Afterwards numen checks the links that pointed to the old name and repairs only those that now point
to nothing. See [links](/links/).

## Removing

**Move note to trash** moves the file into `.trash/` inside the vault, keeping the path it had. It
is removed from search, the plex and the index. Nothing is destroyed, and the file is in that folder
if you want it back.

**Empty trash** deletes everything in the trash of the vault. You are asked to confirm first, and it
cannot be undone. Items that cannot be deleted stay in `.trash/`, and the command reports how many.

Notes that linked to what you removed are reported and left alone. The link is not wrong. Its
target is gone, and only you know what was meant.

## Your files stay yours

numen shares your files with the other programs you edit them in.

- **What it did not change, it does not rewrite.** Your spacing, your line endings and the order of
  your frontmatter keys are preserved as found. A save never produces a diff you did not ask for.
- **Frontmatter that numen does not manage is kept unchanged:** every key your other tools
  write.
- **A file it cannot parse is not repaired.** Broken frontmatter is reported, never guessed at.

## When the file changed underneath you

Edit the same note in another editor, or let a sync client bring down a new version, and the tab
detects that the file changed after it was read. It stops saving at once, keeps every word
you typed, and shows two choices:

- **Keep mine** — write what is in the tab over the file;
- **Take the file's** — read the file again, replacing what is in the tab.

Nothing is decided for you and nothing is lost while you decide. The same choice is shown again
if you try to close the tab or quit the window, and postponing it cancels the quit.

If the file disappears entirely, the tab stays open showing what you were reading and shows that the
note is gone. **Keep mine** creates the file again with that name.

## Limits

|              |                                                                                                 |
| ------------ | ----------------------------------------------------------------------------------------------- |
| One megabyte | the most a single note can be and still open here.                                              |
| UTF-8        | a file that is not valid UTF-8 is not opened.                                                   |
| Prose only   | a note begins below its frontmatter; text pasted in that opens with `---` is refused as a body. |
