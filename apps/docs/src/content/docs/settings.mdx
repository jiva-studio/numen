**Settings** in the commands opens a page over the file: **System**, the settings of the window itself, and under it every plugin installed, each with a page of its own. The search at the top narrows the list by a plugin's name, its description or its kind. The rest of the file is edited in [the file itself](#the-file).

Turning a control writes it down. There is no separate save, and nothing is applied later: a theme chosen here is worn before your hand leaves the mouse.

## System

At the head of **System** is the path of the file the page is a face onto, and **Open the file** beside it — see [the file itself](#the-file).

### The window

| | |
| --- | --- |
| **Theme** | the stylesheet the window wears, in two origins: the ones that ship with numen, and yours. See [themes](/themes/). |
| **Light or dark** | follow the system, or pin one. A theme that declares light and dark itself leaves nothing to choose here, and the control says so. |
| **Interface size** | how large the chrome, the controls and the type in them are drawn. 1 is as designed. |
| **Reading size** | how large the text you read is set, over the size above. |

The two sizes are multipliers over what was designed. The interface goes from **0.8 to 2** and the text you read from **0.8 to 1.75**; hairlines, borders and focus rings stay one physical line under either. A number outside those bounds is rejected, reported with an alert, and left in the file exactly as you wrote it.

### What a note is called

**Sync title and filename** says whether renaming a note renames its file, and the other way round.

## A plugin's page

A plugin's page holds what the plugin declares, and the window's controls over the plugin itself:

| | |
| --- | --- |
| **Enabled** | whether the plugin runs at all. A plugin turned off offers none of its commands, views or texts. |
| **Plugins that stopped** | a plugin the window could not start, with when it gave up and why, and **Retry** or **Disable**. |
| **May ask a model** | for a plugin that asks a model, whether you let it. Until you choose, its first question fails. |
| **Keys** | each key the plugin declares, stored in the system keychain, never in the settings file, and never shown again. |

Under them stand the plugin's own settings, each with the control its manifest declares — a model to choose, a number, a list. The [scanned books](/reader/) and [recordings](/recordings/) pages say which of those are worth changing.

## In the commands

Some of the same settings are in the commands as well — <kbd>Ctrl</kbd>/<kbd>⌘</kbd> <kbd>P</kbd>, under **General**: **Change the theme**, **Light or dark**, **Interface size**, **Reading font size**, **Sync title and filename**, **Set performance profile**. A plugin can offer one of its settings there too, named after the plugin.

A row on the page and the command of the same name go through one piece of code, so it makes no difference which you use.

## The file

Every setting stands in one file, `numen.json`, in [the folder numen keeps its own things in](/install/#where-numen-keeps-its-own-files). **Open the file**, at the head of **System** on the settings page, opens it in a tab of its own, drawn as the JSON it is. Unlike a note it is not written as you type: <kbd>Ctrl</kbd>/<kbd>⌘</kbd> <kbd>S</kbd> keeps it, which is the chord a note is kept by.

A file changed underneath the tab stops saving there and then and asks the same two questions a note does: [keep mine, or take the file's](/editor/#when-the-file-changed-underneath-you). Content that does not match recognized configuration schemas is rejected, and the tab reports an error without saving invalid changes.

It is yours to edit. Fields you leave out keep their defaults, so a file naming one setting is a
complete file. Keys numen does not know are carried through untouched, and a file that does not
parse is never written over — numen says so and leaves it alone.

```json
{
  "appearance": {
    "mode": "system",
    "theme": "preset:numen",
    "interface_scale": 1,
    "text_scale": 1
  }
}
```

## What is in it

| | |
| --- | --- |
| `appearance` | how the window is drawn: the theme, which half of it, the two sizes, and what a node hangs. |
| `indexing.embedding` | how the index keeps the vectors the embedding plugin makes. See [semantic search](/semantic-search/). |
| `agent` | which assistant answers in the panel, and how it is started. See [the agent](/agent/). |
| `naming` | whether a note's title and its filename are kept as one name. See [writing notes](/editor/#renaming). |
| `performance` | how much of the machine the work behind the window may take. |
| `ai.default` | the agent and the model a plugin's question to a model goes to when the plugin names none. |
| `plugins` | each plugin's own settings, under its id. |

[Every setting](/reference/) is the complete list, taken from the application itself.

A key to a service is never in this file: it is entered in the settings of the plugin that uses
it, in the app, and kept in your system's keychain.
