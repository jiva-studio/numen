The plex shows your links around one note at a time. It does not show the
whole vault: it shows the note you are on and every note one link away.

## How it is laid out

The note you are on is in the middle. Around it:

|                                         |                                                   |
| --------------------------------------- | ------------------------------------------------- |
| <span class="up">above</span>           | its parents, the notes it is under.               |
| <span class="down">below</span>         | its children.                                     |
| <span class="across">to the left</span> | its jumps, the links that cross the hierarchy.    |
| to the right                            | its siblings — the other children of its parents. |

A note also shows the notes linked in its text, above and to the left, as references: the ones it links to, the ones that link to it, or both. The References setting of the plugin chooses which.

When you move one step, the map is rearranged around the note you moved to, which is now the middle, with its own parents above it
and its own children below it.

## Moving

|                                             |                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------- |
| Click a node                                | go there. It becomes the middle, and the plex is redrawn around it. |
| Double-click a node                         | open that note in a tab.                                            |
| <kbd>Alt</kbd> double-click                 | open it in a pane beside the one you are in.                        |
| <kbd>Enter</kbd> or <kbd>Space</kbd>        | go to the node the keyboard is on.                                  |
| <kbd>⇧</kbd> <kbd>Enter</kbd>               | open it. Hold <kbd>Alt</kbd> as well to open it beside.             |
| Right-click, or <kbd>⇧</kbd> <kbd>F10</kbd> | the node's menu: everything the commands offer over a note.         |

**Show in plex** on the note you are reading — or <kbd>Ctrl</kbd>/<kbd>⌘</kbd> <kbd>⇧</kbd>

<kbd>P</kbd> — shows the plex for that note.

## What is inside a note

Leave the pointer on a node for a moment and the note's headings appear under the box: the sections of that note, each indented by its depth under the headings above it.

<Shot
  name="parts"
  alt="A node in the plex with the headings of its note shown under the box, indented by depth, and a mark below them showing that there are more."
  caption="Holding the pointer on a node shows what is inside its note."
/>

Click one and that note opens with the caret on the heading's line. **The map does not move.** A
heading is a place inside a note, not somewhere to travel to, so the plex stays on the note it
was drawn around.

Six headings are shown at once. Where a note has more, a small mark at the edge shows it, and the
mouse wheel scrolls through the rest a heading at a time. A node near the bottom of the window shows
fewer, because there is less space below it.

Move the pointer away and they are hidden again.

This works with a pointer only. From the keyboard, [search](/search/) matches headings by name
and opens the note at the one you choose.

**Turn it off** with **Plex Graph: Nest headings under notes** in the commands, and a node shows
its box only. **Headings per note** sets how many are shown at once, from one to twelve. Both are
settings of the Plex Graph plugin, in its section of [the settings](/settings/), stored as
`nestHeadings` in the object `md.numen.views.plex.graph`, and `headingLimit`.

## Notes related to related notes

Under each related note the plex sets, in small grey text, the names of the notes that note is related to: its parents over it, and its children, jumps and references under it. They are a little faded until the pointer is over the note or over the room of its names (how faded is **Names opacity**, `namesOpacity`, from 0 to 1 where 0 hides them until then; how visible they are then is **Names opacity in focus**, `focusedNamesOpacity`, from 0.05 to 1), and a name can be clicked only once it is there: click it and the plex moves to that note. Names are for the pointer alone; the keyboard does not reach them. A name has no pill and no headings, and the lines of the plex do not go to it.

Six names are shown for a note, parents first. A note with more shows the first six. The names take room in the map, so a window shows fewer related notes with them than without.

**Show notes related to related notes** turns them off, and **Names per note** sets how many a note shows, from one to twelve. Both are settings of the Plex Graph plugin, in its section of [the settings](/settings/), stored as `showNames` in the object `md.numen.views.plex.graph`, and `namesPerNote`.

## Building with it

Every node has a small handle: a disc with a cross in it. Press it and drag away from the
node, and a line follows the pointer. Release where you want the new note, and it is created there:
above the node it is a parent, below it is a child, to the side it is a jump.

The link and the note are created together. There is no separate step to connect them. Releasing on empty space opens a quick-link popover: pick an existing note to link to, or type a new title to create and link in one motion.

Clicking the handle directly creates one more child. This is the most common action,
and it is convenient on a trackpad because you do not hold a button down. <kbd>Enter</kbd> on
the handle does the same from the keyboard.

<kbd>Escape</kbd> during a drag cancels it and nothing is created.

## Connecting two notes you already have

The same gesture, released **on another node** instead of on empty space, connects the two rather
than creating a third. The direction you drag in is the relationship: upwards it becomes a
parent, downwards a child, to the side a jump.

So three directions create a link. Siblings are drawn to the right. A sibling
is not a link anyone writes; it is what two notes under one parent already are. So nothing
is created there. Releasing on the node you started from does nothing either.

Notes dragged from the [files tab](/files/#carrying-notes-onto-the-map) work the same way:
drop them into a relation and they are linked to the note that relation belongs to.

## Reading the lines

A line between two nodes is a link. Where you gave the link a
[label](/links/#what-it-looks-like-in-the-file), the label is shown along the line, so the map
tells you _why_ two notes are connected and not only _that_ they are. An arrowhead at an end of the
line is the [marker](/links/#markers) the note at the other end wrote on its link; a link with no
marker is drawn without one.

## Inspecting and changing links

Clicking, or right-clicking, a line between two nodes opens the link inspector. The line to a reference, a note linked in the text, has no inspector: no record joins the two notes.

While the pointer is over a note, every line that joins it is highlighted. **Highlight links of a hovered note** (`highlightLinks`, on by default) turns that off, and then only the line the pointer is over is highlighted. The inspector shows:

- **Arrow**: Each end of the connection can have an arrow, independently of the other. A line with no arrow is plain, and a line with an arrow at both ends has a head at each note.
- **Labels**: Each end has its own label, so the two notes can describe the same connection in their own words. An end with an arrow and no label is kept.
- **Delete links**: Remove one end or the entire connection between the notes.

Saving the inspector updates the frontmatter `links:` block in the notes.
