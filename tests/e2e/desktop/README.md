# Desktop end-to-end tests

`npm test` (and `npm run test:flashcards`) runs Playwright against the debug server of `scripts/start-server.mjs` (`scripts/start-flashcards-server.mjs`): a temporary vault holds the config, cache, data and home folders, the plugins run on mock models with empty placeholder dependencies, and `scripts/stand-ins.mjs` serves the release manifest and the chat API on loopback.

The servers are the debug builds of the two windows, `apps/desktop/numen-debug` and `apps/desktop/numen-flashcards-debug`, built with the `numen_debug` tag (`go build -tags numen_debug -o numen-debug ./cmd/numen` in `apps/desktop`, and the same for `./cmd/numen-flashcards`); `make app_desktop_e2e` builds both.

On Linux `scripts/run-offline.mjs` runs the suite inside `unshare -rn` with loopback alone, so a scenario that connects to the internet or production fails; give it a local stand-in instead.

`npm test` runs every engine and shard at the same time, each as a Playwright process with a debug server, a temporary vault and a config, cache, data, state and home folder of its own. The specs of one server share its settings, open tabs, trash and vault list, so the spec files of a shard run one after the other, and a shard is a share of the spec files. `shards.json` lists every spec file with the seconds it takes, and `scripts/shards.mjs` deals the files out by those seconds, longest first. `npm run lint` (`npm run shards:check`) fails on a spec file that `shards.json` does not list; `NUMEN_E2E_JSON_DIR=<dir>` has each process write a JSON report there, and `npm run shards:measure -- <dir>/*.json` writes the seconds of `shards.json` again from them. `--shards=<n>` (or `NUMEN_E2E_SHARDS=<n>`) sets the shards for each engine; the default is half the cores, at most four, and one when the run names a file or a filter. A server counts as started once its vault is read and no task runs, and the script then prints `numen e2e: the vault is indexed`, which Playwright waits for. The process number n listens on `NUMEN_TEST_PORT` (3456) + 10 * n. `npm test -- --project=webkit` runs one engine, and `npx playwright test` without the runner runs every file against one server on `NUMEN_TEST_PORT`.

`NUMEN_E2E_PATHS` limits a run, and its shards, to the folders and spec files it names, separated by spaces (`tests/shell/ tests/plugins/readers.pdf/`). CI (`.github/workflows/desktop-e2e.yml`) builds once and runs every engine and shard on a runner of its own, one Playwright process each, with `NUMEN_E2E_SHARD=<index>/<count>`. `scripts/select-tests.mjs scope` reads the changed paths of a pull request and prints the scope it needs, and `scripts/select-tests.mjs plan <scope>` the jobs that run it: a shard holds about five minutes of tests by `shards.json`, at most four for each engine.

The window is WebKitGTK on Linux and WKWebView on macOS, so the suite runs in WebKit as well as Chromium. The reports are written to `playwright-report/<project>[-<shard>]` (`npm run test:report -- playwright-report/webkit-1`) and the traces in `test-results/<project>[-<shard>]`. WebKit on Linux uses glib-networking for https to the debug server: a distribution installs it where GLib looks for it, and on NixOS the runner takes it from nixpkgs and sets `GIO_EXTRA_MODULES`.

The debug server makes a certificate at start and writes it to `$TMPDIR/numen-e2e-certificate-<port>.pem`. Chromium aborts the first handshake of each context with a certificate it does not trust, even with `ignoreHTTPSErrors`, so the `test` of `tests/support/certificate.ts`, which `tests/support/test.ts` and the flashcards specs build on, launches it with `--ignore-certificate-errors-spki-list` set to the hash of that certificate's public key, read when the worker starts. Its key goes to `$TMPDIR/numen-e2e-key-<port>.pem`, and a server a spec starts with `tests/support/server.ts` serves that same pair (`NUMEN_DEBUG_TLS_USE_CERT`, `NUMEN_DEBUG_TLS_USE_KEY`), so the one hash covers it; it counts as started once it has written the certificate to its own folder. The flashcards server writes its certificate, without a key, to the same name for its port. Playwright stops the servers with SIGTERM, and the start scripts remove the certificate, the key and the vault of the run.

The debug server serves the window's page with `/numen-debug/fetch.js` loaded first, which sends the page's calls as PUT, and handles a PUT as POST. WebKit on Linux (libsoup) opens a connection for every POST, even over HTTP/2, and at most six to one host; the window keeps more server streams open than that, so without it every call after the sixth stream never completes. A PUT shares one HTTP/2 connection with everything else. The window itself uses `wails://`, where no connection is opened.
