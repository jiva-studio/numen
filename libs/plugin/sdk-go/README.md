# Numen Go Plugin SDK

Backend server lifecycle SDK for native Numen plugins.

## Modules

The SDK is a base module and a feature module in each folder that has a `go.mod`. A plugin requires the base module and the feature modules it imports, each with a `replace` to its folder. A feature module requires the base module at most and no other feature module.

| Module                | Packages                                                                               | Provides                                                                                                                                                                                                                                              |
| --------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plugin/sdk-go`       | `server`, `connection`, `tools`, `health`, `hostcall`, `cache`, `shared`, `plugintest` | the server lifecycle every native plugin runs under; `connection` the provider of a connection type and the client of a plugin that asks for an operation; `tools` agent tools; `health` whether the plugin works; `hostcall` the clients of the host |
| `plugin/sdk-go/host`  | `host`, `host/hosttest`                                                                | reading and writing the vault through the host                                                                                                                                                                                                        |
| `plugin/sdk-go/wasm`  | `wasm`                                                                                 | the compilation cache of a plugin that runs WebAssembly                                                                                                                                                                                               |

`make lib_plugin_sdk_go_lint`, `lib_plugin_sdk_go_build` and `lib_plugin_sdk_go_test` run over every module.

## Capabilities

- Automatic CLI flag parsing (`-port`, `-token`) with `NUMEN_PLUGIN_PORT` and `NUMEN_PLUGIN_TOKEN` environment variable fallbacks.
- `cache.GetPluginDir()`, `cache.GetDataDir()`, `cache.GetSharedDir()` and `cache.GetSharedDataDir()` return the directories the host created, from `NUMEN_PLUGIN_CACHE_DIR`, `NUMEN_PLUGIN_DATA_DIR`, `NUMEN_SHARED_CACHE_DIR` and `NUMEN_SHARED_DATA_DIR`, and an error where the host gave none; `cache.GetSharedDirOrPluginDir()` and `cache.GetSharedDataDirOrPluginDataDir()` fall back to the private directory for an older host. The first two are private to the plugin. The shared ones hold one copy of what every plugin uses: compiled CoreML models in the cache one, models in the data one (the OS may purge a cache, and a model is gigabytes), named by digest, written atomically, never deleted by a plugin. A plugin never computes a platform path. `plugintest.GrantStorage` sets all four for a test.
- `shared.Lock(dir)` takes the operating-system file lock of a directory of the shared directory, so two processes that compile or write the same entry do not run at the same time; `shared.GetModelKey(path)` is the digest that identifies the data derived from a model.
- `wasm.NewCompilationCache(dir)` is the compilation cache of a plugin that runs WebAssembly, stored in a folder of the directory the host granted and in memory where that folder cannot be used.
- Host handshake signaling via `NUMEN_READY port=<port>`.
- Connect-RPC Bearer token authentication interceptor for unary and streaming RPCs.
- Graceful lifecycle management (`Ping`, `Configure`, `Shutdown`) without unowned goroutines or sleep synchronization.
- `Configure` is how a plugin receives its settings. The callbacks of `WithConfigure`, `WithUpdateConfig`, `SetConfigure` and `SetUpdateConfig` take the settings as a map of text.
- `WithEventHandler(fn)` mounts `PluginEventService`, so the host delivers to the plugin each event its manifest's `activationEvents` subscribe to. An error the handler returns is reported as the plugin's error for the event, with its text as the reason. A server without one receives no events.
- No exported identifier of the SDK mentions a type of `libs/core/protocol/gen`. Each package defines its own types and interfaces (`tools.ToolInfo`, `searchsource.Description`, `command.Request`) and converts them to the wire messages in unexported code; the Connect handlers and clients are built inside the package (`tools.NewClient`, and `servertest.NewLifecycleClient` for plugin tests). A plugin compiles against the SDK without importing the protocol. The test `SDKProtocolRule` in `libs/core/kernel/container` rejects a new leak, and each conversion has a round-trip test.
- Process supervision hooks (stdin EOF detection, OS signals).
- `Server.NewAPI(service)` serves the JSON methods of a plugin's own frontend under a service name the manifest declares in `services`: `server.Handle(api, "Method", fn)` mounts `POST /<service>/Method` for a function of a request struct returning a response struct, and `server.Stream` mounts a method that responds with Server-Sent Events (`data:` per response, a final `error` or `end` event). The host token is checked on every call. A function fails with `NewAPIError(code, message)`; any other error returns `internal`. The request and response types are defined by the plugin. `createApi(service)` in `@numen/plugin-sdk` is the client: `call` returns a `Result`, `stream` is an async generator.
- `NewLinkedHandler(vars, mount)` returns the handler for a host that links the plugin into its own process. It is a server with the services that `mount` registers on it. It takes its token from the variables the host gives the plugin and reads no flag. `Server.OnClose(fn)` adds what runs when `Serve` returns, or, for a linked server, when the host shuts the plugin down.
- `agentrun`: `Discover` finds a program on the path or in the standard and program places; `Locate` finds an agent program on the path or in the places it is installed to; `CreateTempDir` creates a temporary folder with a clean-up function; the registry of the runs an agent plugin has started and the session each conversation is on, and the supervision that ends a child and everything it started. `Start` runs a child that writes one JSON event per line and returns the work that reads it, `ForwardResponses` sends the work to the `send` function of `Runner.Ask`, and `Service` handles `RegisterTool`, `ExtendSystemPrompt`, `GetTools` and `FinishConversation` for a plugin that embeds it. A plugin implements the `Runner` and `ToolStore` interfaces over the SDK types `Request`, `Response` (a `Step` of `TextStep`, `ToolCallStep`, `StoppedStep`, `ToolFinishedStep`, `ModelStartedStep` or `EditProgressStep`), `State`, `Program` and `ToolSet`, and `NewHandler` serves both; `Client` and `Unimplemented` are the client and the default for the calls a plugin does not handle. The SDK types convert to the protocol messages in one unexported layer that no exported identifier mentions.
- `connection.Mount(s, provider)` serves the roles of a provider of connection types over `ProviderService` (`Completer`, `Chatter`, `Embedder`, `ModelLister`, `ProfileReader`), and a call fails with `NewTryNextError(reason, retryAfter)` or `NewStopError(reason)`; `connection.NewClient(...)` returns the `Client` with which a plugin asks the host to `Complete`, `Chat`, `Embed` or `GetEmbeddingProfile` on the connections of its own rows and gets `ErrNoConnection`, `*AllFailedError` or `*RejectedError` where none answers. A `Secret` shows no value when printed, logged or encoded. `connection.ReadRows(values, key)` reads the rows of a setting of type `connections` from the values of `Configure`, and the `Row` it returns holds the opaque id of the connection, the model and the reasoning level. See [Writing a provider](../../docs/plugins/providers.md) and [Rows of connections](../../docs/plugins/connection-rows.md).
- `agentrun.HasTools(req)` reports whether a task names a tool of the vault. A task that names none is a single answer, and the program receives no tool. `agentrun.WritePrompt(instructions, prompt)` puts the instructions before the prompt for a program that takes no system prompt.
- `health.Report(ctx, health.Item{Key, Severity, Text, Detail, Action})` puts an item of the plugin in the host's list of health items, or replaces the one under its key, and `health.Clear(ctx, key)` takes it out; `health.NewClientFromVars(vars)` is the client of a linked plugin. An `Error` item shows in the window's list of tasks and on the plugin's page, a `Warning` item on the page only. `health.OpenSettings(setting)` is the action that opens the plugin's settings with the setting marked; any other action names an `app:` command or a command of the plugin, with values its arguments declare. The host refuses more than 8 keys, a text over 120 characters, a detail over 500 and the keys `configure`, `start` and `search`, which are its own. `healthtest.NewHost(t)` keeps the items a plugin reports, for tests.
- `searchsource.Mount(s, handler)` serves a search source over `SearchSourceService` (the manifest declares the `search.source` capability): `Describe` names the recipe, the width of the vectors and the chunk size, `IndexTexts` answers one vector per text the core hands it with the place its vectors are kept in, `SearchPassages` answers the chunks of the place that answer a query, best first, `DescribeCoverage` answers the text a person reads about the index, and `EmbedQueries` answers the vectors of queries. `host.PlaceSearch` finds the chunks of the place nearest a vector through `HostSearchService.FindNearestPassages` (it needs `index:read`).
- `tools.Registry` contains the tools a plugin offers an agent, served as `PluginToolService` once `Mount`ed (the manifest declares the `tools` capability). `tools.Add(registry, spec, run)` adds a tool from a function that takes an argument struct and returns a result struct: the schemas given to an agent are derived from the two structs, a returned error becomes a tool error result, and `spec` names the tool, its effect (`Reads` needs `vault:read`, `Writes` needs `vault:write`), the servers it is offered on and how a call is shown. The host lists the tools of every running plugin that declares the capability and requires for each the permission its effect needs. `spec.Instructions` are the sentences an agent reads about the tool before it calls it, one sentence each; a sentence about several tools is given to each of them with identical text. An agent server sends an agent the distinct sentences of the tools it offers, in listing order. `spec.Requires` names the permissions a caller must hold besides the one of the effect, such as `vault:manage`: the host lists and runs the tool only for a caller holding all of them. `ListTools` returns a `tools.Listing` of the tools.
- `host.Client` reads and writes the vault the window shows through `HostVaultService`: files with their stats (`Write` returns `ErrStale` for a file that changed since its baseline), the notes, types and links the index holds, its cache and a watch, whose last message contains the failure that ended it. Its signatures use the note types under the names of `host/domain`, the one package that names them; `host/domain`, `host/markdown`, `host/edit` and `host/ulid` re-export the note types, the note parser, the editor and the identifiers of `libs/note`, so a plugin imports them from the SDK and never imports `libs/note`. The SDK requires `libs/note`, which is published and tagged together with the SDK. `host.StoreClient` reads and writes the plugin's own folder of a vault's store, `.numen/<plugin id>/`, through `HostStoreService`, behind the `host.StoreReader` and `host.StoreWriter` interfaces. `hosttest.Vault` is a vault in memory that implements the same capability interfaces as `host.Client` (`host.FileReader`, `host.FileWriter`, `host.NoteLookup` and the others) for tests, and its `Store()` implements `host.StoreReader` and `host.StoreWriter`. `hostcall` reads the host endpoint and the token from the environment and sends the token on unary and streaming calls.
- `host.SearchIndex`, `host.PassageSearch` and `host.SearchPolicy` provide the search index and the search floor of the vault the host shows, through `HostSearchService`: `GetEmbeddingState` (the model in use and how far the vault is embedded, read from the index at each call), `GetIndexStats` (what the index holds: chunks, vectors, sources by file extension, and its size on disk), `EmbedTexts`, `SampleSimilarities` (the host compares query vectors with the passages of other notes and returns the similarities) and `GetBestSimilarity` (they need `index:read`), `GetSearchFloor` and `SetSearchFloor` (they need `search:policy`). A sample is capped at `MaxSampledQueries` queries and `MaxSampledPassages` passages, a query of another dimension count is `ErrInvalidQuery`, a floor outside zero to one is `ErrInvalidFloor`, and a recipe of another model is `ErrRecipeMismatch`. `host.ReadSearchSourceReadyEvent` reads the event the host emits when the search source has indexed a vault. `host.SearchClient` uses it through the host, and `hosttest.Search` implements the same interfaces in memory for tests, with `Deny` for a missing permission and `With` for another vault.
- `host.TextVersions` and `host.TextReader` provide the text versions of the vault the host shows: `PutVersion` reports a version of the plugin (who made it, from the file or from another version, its format and the hashes of its input and of itself), `ListVersions` returns the live one, `ReadText` reads any version a page at a time through the host and `ReadWholeText` joins the pages. `TextClient.With(vault)` uses the texts of the vault a request names, as `StoreClient.With` does. `host.TextClient` uses it through `HostTextService`. A plugin makes its text when its handler of `app:file.createText` runs, from a person, numen-cli or its trigger. The core deletes a version, its record and its file, through the application command `app:version.delete`; a plugin writes no deletion of its own. `hosttest.Texts` is in memory, for tests.
- `toolcall.Describe(words, name, call, args)` returns the description of a vault tool call as shown to a person, derived from the `ToolDeclaration`s of the task; `toolcall.ReadPartialField` reads a field of arguments that are still being received.
- The `clock` package holds the time sources of a plugin: `clock.System` reads the machine time and the plugin entry point passes it to the packages it constructs, and `clock.Fake` reports a configured time that tests move with `Set` and `Advance`. A package declares the one-method interface `Now() time.Time` it needs and receives a clock through its constructor; `time.Now`, `time.Since` and `time.Until` are rejected by the Go lint configuration.
